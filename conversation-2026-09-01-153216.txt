  Step 2: Details

  Project Details

  ▎ Every Solana developer and power user has stared at a failed transaction 
  ▎ with nothing but custom program error: 0x1771 and a wall of logs. Explorers 
  ▎ show what happened; nothing tells you how to fix it. Developers lose hours 
  ▎ cross-referencing IDLs, Anchor error codes, and Discord threads for failures
  ▎ that have well-known, documented fixes.
  ▎
  ▎ TxWhy closes that gap. Paste a failed transaction signature (or explorer 
  ▎ URL) and TxWhy fetches the transaction, renders the full instruction/CPI 
  ▎ tree with the failing instruction highlighted, and decodes the error to 
  ▎ plain English — cause plus suggested fix — through a three-layer decoder: a 
  ▎ known-program registry (System, SPL Token, ATA, Compute Budget, Jupiter, 
  ▎ Metaplex), Anchor custom-error decoding via published IDLs, and a curated 
  ▎ JSON knowledge base mapping error patterns to { cause, fix }, organized 
  ▎ around a six-category failure taxonomy (account / balance / timing / program
  ▎ / provider / size).
  ▎
  ▎ Unlike AI-only explainers that regenerate a different answer per query, 
  ▎ TxWhy's knowledge base is deterministic, citable, and version-controlled — 
  ▎ the same error always gets the same verified fix with links to docs, and 
  ▎ anyone can extend it via PR. Every trace gets a shareable permalink 
  ▎ (/tx/[signature]), so instead of pasting raw logs into a support channel, 
  ▎ you post a TxWhy link.
  ▎
  ▎ The project is built agentically end-to-end with Claude Code on the 
  ▎ solana.new (superstack) toolchain: Next.js App Router + TypeScript on 
  ▎ Vercel, public Solana RPC (getTransaction, simulateTransaction). Week 1 core
  ▎ is already shipped — end-to-end transaction tracing with the program 
  ▎ registry, error decoder, and permalink trace pages. The roadmap extends the 
  ▎ KB to 150+ errors, adds an embeddable pre-send simulation widget, and a 
  ▎ public API — and the project is entering the Colosseum hackathon (Sep 28 – 
  ▎ Nov 2, 2026).
